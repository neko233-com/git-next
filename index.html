Windows: the Git-Terminal 0.2.0 complete MSI bundle includes the accepted git-next 0.3.0 engine with the updated SSH/SFTP/monitoring terminal and prompt latency fixes. Existing installations should use its install_bundle.ps1 helper; see the component installation guide. Linux/macOS core packages are unchanged.

简体中文 · Git guide · Manual · Why git-next · Delivery status · Documentation site

git-next is a complete source-built Git client with its own product identity, cross-platform LF defaults, and native English/Simplified Chinese messages. The primary engine is the full native C command, repository and protocol implementation based on Git 2.54.0; it does not fall back to an installed Git or OpenSSH. Existing repositories, Git configuration and credential helpers keep their normal contracts.

Version 0.3.0 passed the final 18-case local correctness evidence and paired performance batch. Original Git has been uninstalled and the workstation default is git-next. Publication and the completed 10/10 scope are recorded in delivery status. Windows ships tested serial index/grep reads with fscache/fsmonitor/preload disabled; full large-tree scans remain a measured latency limitation, documented in performance.

Native packages

Download accepted packages from GitHub Releases. Candidate build output is not an installation recommendation. Released Windows packages include the owned runtime and require no Rust compiler.

git --version identifies git-next and its compatibility baseline. Normal Git commands, plumbing, hooks, signing, LFS, credential helpers, submodules and linked worktrees use the full native engine. User-configured hooks, filters and helper programs retain their normal Git behavior.

Unconfigured text uses LF consistently across platforms. Explicit repository attributes, binary/LFS rules and configuration retain their priority. New repositories remain empty after init. git eol --apply explicitly installs missing shared LF/editor policy; it does not silently rewrite every existing project. Pure line-ending changes are compared canonically, while content/serialization changes remain visible. LF policy.

Language follows system preferences and supports persistent and per-command overrides. Machine formats remain stable. Automatic updates select official GitHub metadata, probe official/mirror download routes concurrently and verify downloaded bytes; mirrors cannot choose the release or provide its trusted identity. Evidence and source

Validation runs locally, with independent correctness lanes in parallel and Windows Installer transactions serialized. Reports retain actual elapsed time and failures. Performance uses a separate paired batch; measured medians, p95 and primary-process memory determine claims. No universal speedup is promised. Builds · Performance · Compatibility.

The native core is GPL-2.0-only with the declared dependency licenses and corresponding source bundles. Source/license delivery. No GitHub Actions are used.

Windows one-click installation

After obtaining the official release's install.ps1, run powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1. This automatically replaces registered Git for Windows, preserves configuration/login/repositories and records a protected rollback transaction. -Plan inspects the selection without changes. Offline MSI/TLS material and checksum requirements are documented in installation.

Windows MSI installs the independent Rust + GPUI Fast Git-Terminal beside Git-next, with tabs, Unicode/IME, copy/paste, scrollback and owned Bash plus PowerShell/CMD profiles. It replaces the Git Bash desktop entry and adds no Git GUI menu. Built-in LFS and game profiles cover Unity/Tuanjie and Unreal; no separate LFS installer is needed.
