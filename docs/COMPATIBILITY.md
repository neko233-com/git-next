# Compatibility contract

The primary native product uses the complete source-built Git 2.54.0 command/repository/protocol engine, with git-next branding, LF defaults and language/update extensions. Existing repository storage, standard flags/machine formats, hooks, credential helpers, signing, LFS, submodules and linked worktrees retain their compatibility contracts. Explicit user configuration retains priority. The owned runtime supplies SSH/shell/interpreter/helper dependencies; an installed original Git/OpenSSH is not a fallback.

`packaging/native-compatibility.json` describes native command coverage; package `release_eligible` remains a separate local correctness/performance release gate. The root `compatibility.json` and the subset descriptions below belong to the historical Rust preview. They do not limit the native C engine or authorize that preview for takeover. [Current evidence](DELIVERY_STATUS.md) and [platform requirements](INSTALLATION.md) define the accepted delivery scope.

## Historical Rust preview subset

- `init [directory] [--bare] [-b branch]`: main default, existing repositories are not reformatted.
- `clone URL [directory] [--bare] [-b branch] [--depth n]`: native HTTPS/SSH, shallow network clone, SHA-1 local clone. Refuse an existing destination. Local sources with detached HEAD require an explicit branch; local shallow clones refuse.
- `fetch [remote]`: native network transfer and common configured ref updates; local default wildcard branch refspec. Existing objects reused. No complete prune/tag/custom-refspec parity.
- `push [-u] [-n|--dry-run] [--all|--tags|--delete] [--atomic] [--force|--force-with-lease[=REF:EXPECTED]] [remote] [refspecs...]`: native local-bare, HTTPS and embedded SSH transfer, normal branch/tag refspecs, annotated tags, upstream settings and configured tracking-ref mappings. Non-fast-forwards, stale leases, server rejections and duplicate destinations fail. Explicit refspecs, push.default simple/current/upstream/matching/nothing and remote push URL selection are supported. Wildcard push refspecs, multiple push URLs, complete output parity and native receive-pack service remain open. Recognized standard LFS pre-push hooks use the native LFS upload path; customized pre-push and local receive hooks refuse until hook execution is implemented. Local receive policy includes denyDeletes, denyNonFastForwards and denyDeleteCurrent; non-atomic partial failures record accepted refs, atomic rejection does not report partial success. Tracking updates compare-and-swap their pre-push values so concurrent local changes survive.
- `switch [-c new-branch] [--detach] [revision]`, `checkout [-b new-branch] [--detach] [revision]`: clean ordinary-file worktrees, local branches, creation and detached HEAD. Preserve unrelated untracked/ignored files and unchanged tracked files; refuse collisions, staged/unstaged changes, linked worktrees, active checkout/merge hooks, symlinks, submodules, sparse/conflicted indexes and unsupported paths.
- `pull --ff-only [remote]`: fetch the configured upstream and update HEAD/index/worktree on a fast-forward. Already-current and locally-ahead branches succeed without moving HEAD; divergence refuses. Fetch may update remote refs/objects before a later worktree refusal. Plain `pull` still refuses.
- `merge [--ff|--ff-only|--no-ff] [--no-commit] [-m message|--no-edit] [--cleanup mode] revision`, `merge --continue`, `merge --abort`: [ordinary two-parent subset](MERGE.md), including simple conflicts, standard merge state and conservative abort of native merges. Annotated tags, autostash and complex rename/tree conflict recovery refuse. Full merge/editor/recovery behavior remains open; exact installed scope is recorded separately.
- `add [-A] [literal paths...]`, `commit -m message`, `commit --no-edit`: native ordinary unsigned commits and completion of a supported single-head merge. `--cleanup` overrides the configured cleanup mode. Root-relative paths only; no magic pathspec, sparse index, active hooks, signing or rebase/sequencer state. Interactive message editing and non-UTF-8 commit encoding refuse.
- `restore` and `reset`: [ordinary-file/index/ref subset](RESTORATION.md), including partial paths, soft/mixed/hard, ORIG_HEAD, reflogs, detached/unborn branches and writer-lock protection. Full parity remains open.
- LF defaults and `add --renormalize`: [cross-platform line-ending policy](LINE_ENDINGS.md), with shared Git/EditorConfig rules for new working repositories, local clone settings, binary/explicit-exception preservation and canonical filtered status. Existing tracked bytes are never renormalized automatically.
- `status [--porcelain|-s]`, `log [-n count] [--oneline]`, `branch [name]`, `remote`, `config`, `rev-parse`, `hash-object`, `cat-file`, `ls-files`, `show-ref`, `ls-remote`: implemented flags are visible in `--help`; do not assume general Git CLI/output parity.
- `config`: default/--global/--local/--system/--worktree/--file scopes, get/get-all/get-regexp/list, add/set/replace-all/unset/unset-all, common modern get/set/unset/list forms, bool/int/bool-or-int/path conversions, value matching, NUL output, defaults and origin/scope output. Implicit booleans remain distinct from explicitly empty values. Includes and repository-conditioned includes are followed when requested; config writers take an exclusive lock, reread the current file and preserve unrelated comments. Full URL-match/color/date/edit/section-management and regex dialect parity are not yet accepted.
- Global `-c KEY=VALUE`, repeated `-C`, `--git-dir`, `--work-tree`, `--bare` and GIT_DIR/GIT_WORK_TREE/index environment context feed native repository discovery. Root `-c` settings reach network transport and credential configuration. Clone rejects global repository-location overrides before writing instead of silently applying them to a different destination. Windows rev-parse paths omit the native extended-path prefix and use Git path separators.

## Not implemented / not accepted

Native `diff`, `show` and expanded formatted `log` are implemented in the [declared read-command subset](READ_COMMANDS.md). The current Windows read-command checkpoint is recorded in [acceptance](ACCEPTANCE.md). Full diff/history semantics remain open.

Receive-pack service, complete reset/restore/merge/recovery, rebase/cherry-pick/revert/bisect, stash, full diff/blame, complete LFS/locking/SSH-LFS behavior, submodules, sparse/partial clone, complete credential helpers, reftable, linked worktrees, complete hooks/signature/config/pathspec/rename parity and IDE integrations. SHA-1/SHA-256 merge and commit-message fixtures are covered separately; full SHA-256 network/repository workflows remain open. Unsupported commands/options must fail clearly. In particular, an official Git version parser must not infer official Git feature support from git-next's own product version.

## Required repository extensions

Opening validates the local format before constructing a reference store and validates included effective configuration again. Unknown required version-1 extensions, reftable/unknown reference storage, promisor layouts and incompatible object-format extensions refuse before writes. Ordinary files references, supported SHA-1/SHA-256 objects, precious-object retention and optional unknown version-0 keys remain compatible. No conversion to files refs, layout migration or object deletion is attempted. `tests/repository_format_acceptance.py` checks exact repository snapshots after refused status/add/commit/reset operations. [Git format negotiation contract](https://git-scm.com/docs/repository-version).

## Index staging consistency

Native staging resolves file/directory index conflicts when a selected child replaces an indexed ancestor file or a new file replaces indexed descendants. Prefix removal is bounded to that subtree; similar neighbor names and unselected edits are preserved. Per-operation parent checks prevent old tracked child paths from traversing a replaced file/symlink parent. Renormalization requires selected tracked paths and their parent directories to remain present; missing/replaced paths fail before object/index writes. Add and commit verify stage-zero index path consistency before publishing an index or building a commit tree. `tests/add_directory_acceptance.py` checks reference stage/tree IDs, no-write refusals, symlink boundaries where supported and malformed-index commit refusal. Current accepted bytes remain in [acceptance](ACCEPTANCE.md).

`add --renormalize` skips unresolved index stages; ordinary stage-zero entries, including intent-to-add, follow the tested reference behavior. Missing selected tracked paths refuse without repository writes. These guards preserve conflict resolution and require an explicit operator decision before normalizing a replacement/deletion.

## Status metadata cache

The source keeps tracked file rows separate from same-name untracked directory rows. Ordinary mode retains the tested Git directory-collapse behavior, including nested untracked repositories and indexed file replacements; `-uall` retains selected child paths. A staged deletion and same-name untracked directory can both remain visible. Empty directories do not erase a tracked deletion. See `tests/status_directory_acceptance.py` and [acceptance](ACCEPTANCE.md) for the exact accepted bytes. Complete submodule behavior remains open.

Status may refresh verified stat-cache data under an optional index lock acquired before scanning. It preserves staged object IDs and HEAD, skips writing when another writer holds the lock or `GIT_OPTIONAL_LOCKS=0`, and leaves v4/split/sparse/untracked-cache/unknown-extension index layouts untouched. Automatic refresh is limited to ordinary v2 indexes with recognized cache extensions and a valid or explicitly omitted checksum. A custom `GIT_INDEX_FILE` is locked using its complete filename plus `.lock`; existing index permissions are retained. Read-only and indirect index files are not rewritten. Full index/status/output compatibility remains open.

The Windows directory cache now shares lazy listings among the workers of one scan while retaining local lookup maps and live fallback for missing metadata. A subsequent scan starts fresh; `core.fscache` remains honored. This changes in-memory resources only, with no object/ref/index layout or settings migration. Matching Windows optimized/installed conformance and scoped performance are recorded in [acceptance](ACCEPTANCE.md); details and rollback are in `vendor/gix-status/PATCHES.md`.

Status uses the full HEAD/index comparison and passes the same pinned index snapshot to worktree/untracked scanning. An attempted serial HEAD/index shortcut was rejected after measured regression; its experiment is retained in [performance](PERFORMANCE.md). Existing cache-tree data does not replace verification of staged changes, and no cache-tree or repository format migration is performed. [Git cache-tree format](https://git-scm.com/docs/gitformat-index).

Status defaults to plain long output, with staged/unmerged/unstaged/untracked/ignored sections, hints, branch/upstream state and ordinary submodule change notes. `--long`, `status.short`, `status.branch` and `advice.statusHints` control the supported output; explicit formats override configuration and the last format wins. Long status reads common merge/cherry-pick/revert/bisect/rebase/am summaries without implementing those operation mutators. Rebase metadata is bounded to 64 KiB per file; unsupported todo commands and malformed state refuse before optional index publication. `--long` and `-z` are incompatible. Stash/color/column/localized output and complete formatting configuration remain open. Existing repository/index/storage layouts do not change; rollback is the previous binary.

Status lists tracked changes before untracked paths with raw-byte path ordering and retains a staged deletion alongside the same-name untracked file. The source supports porcelain v1 (`--porcelain[=v1|1]`), porcelain v2 (`--porcelain=v2|2`), `-s`/`--short`, NUL records (`-z`), attached `-u` modes and `--untracked-files`, and native pathspecs. Normal records quote special names using `core.quotePath`; NUL records preserve raw filename bytes and emit rename destination before source. Porcelain/NUL paths remain root relative; ordinary long/short paths honor `status.relativePaths`. Canonical LF/CRLF-only saves remain clean even when reference Git's size shortcut reports a false modification; normalized object hashes determine that intended behavior.

V2 records include full object IDs, file modes, rename scores and all seven conflict masks. Similarity scores count reusable LF/64-byte spans; full rename candidate selection, driver and large-blob compatibility remain open. Branch headers support unborn/detached branches, configured upstream refs, missing refs and native ahead/behind counts; `--no-ahead-behind` avoids the history walk. Ordinary submodule read status distinguishes commit, tracked and untracked changes, with CLI/configured ignore modes. Every supported format is fully prepared before optional index refresh. Stash headers, complete long-output configuration, full submodule operations/recursive behavior and complete IDE/CLI parity remain open. See [read-command scope](READ_COMMANDS.md) and [acceptance](ACCEPTANCE.md) for the exact accepted bytes/platforms.

The native ignored-status subset supports `--ignored[=traditional|matching|no]`, v1 `!!` and v2 `!` records after untracked rows, NUL/raw filenames, global/info/worktree ignore sources, forced tracked ignored paths and nested repository boundaries. Traditional mode collapses ordinary ignored directories unless `-uall` requests their files; matching mode retains explicitly ignored directories, including empty directories. The reference matching-mode common-prefix behavior for directory pathspecs is preserved, including per-file exclusion differences. `matching` with effective untracked mode `no` refuses before taking the optional index lock. Ignored traversal is requested explicitly; ordinary status retains its existing scan. `tests/status_ignored_acceptance.py` pins SHA-1/SHA-256 snapshots and reference bytes. This does not establish full ignore/pathspec/IDE parity or change repository/index/storage layout; rollback is the previous binary.

Status validates rename boolean/`copy`/`copies` values, nonnegative 32-bit rename limits, path quoting/relativity, untracked-file mode and its supported diff algorithms before taking the optional index lock. Invalid values refuse instead of being dropped by a lenient reader. Status rename keys belong to the `status` section, take precedence over diff defaults and do not use unrelated merge settings. CLI untracked selection overrides configuration, and untracked pathspec collapse preserves the tested Git directory/file representation. The current status subset accepts myers/default/minimal/histogram; patience and complete configuration/algorithm parity remain open.

The full comparison preserves configured platform path-component protection, including protected `.git` names and symlink `.gitmodules`. Both object formats refuse malformed matching HEAD/index/cache fixtures without changing repository bytes. The isolated malformed-input tests protect this behavior while the implementation evolves.

Conflict paths remain tracked even when the index has only a base/theirs stage and no ordinary/ours entry. They must not also appear as untracked files. The v1/v2 conflict fixture checks existing worktree files for all seven masks on both object formats and container platforms.

## Native LFS subset

Pointer/cache, clean/smudge/filter-process v2, local install/track, HTTPS batch/basic transfer and upload-before-push are implemented. Standard LFS filters use the sibling native executable; root `-c` settings propagate to filter children. Standard LFS hooks are accepted only when lock management is not needed. Custom hooks and lockable-file permission/verification semantics refuse before writes. See [LFS implementation and acceptance](LFS.md).

## Existing HTTP login and transport settings

Credential Get requests use the existing Gitoxide helper cascade, including URL-specific settings, helper resets, username, useHttpPath and expiry handling. Named helpers resolve to `git-credential-NAME` directly; literal executable paths, including spaces and Windows short names, run without an external Git dispatcher or an implicit shell. Explicit shell-script helpers retain their configured shell dependency. Network authentication does not automatically store or erase saved credentials after success/failure. Missing helpers fail clearly; Windows Credential Manager helper packaging and real existing-login acceptance remain required before uninstalling the original Git distribution.

The reqwest transport honors a configured CA bundle while retaining certificate validation and HTTPS downgrade checks. Authenticated TLS fixture acceptance uses a generated private CA through `http.sslCAInfo`, not disabled verification. Existing explicit sslVerify, proxy/no-proxy, timeout and user-agent settings reach the native client. Plain HTTP credentials remain refused by default. See the documented dependency changes under `vendor/gix-credentials/PATCHES.md` and `vendor/gix-transport/PATCHES.md`.

## Embedded SSH

Strict known_hosts verification is mandatory; unknown/changed host keys reject. Supported subset includes Host/Include, HostName, User, Port, IdentityFile, IdentityAgent and UserKnownHostsFile, with first-match semantics. Keys and the native agent are attempted with bounded authentication attempts. Match, ProxyCommand/ProxyJump, agent commands, certificates/security keys and unsupported authorization modes refuse. An explicitly configured encrypted-key passphrase or password may be supplied through private process environment; never place it in a command, repository or report. The project does not alter system SSH settings or known_hosts automatically.

## Data and rollback

Use disposable repositories first. Index locks use exclusive creation; ref updates use Gitoxide compare-and-swap semantics. Local clone publishes a complete temporary destination, never hard-links source objects. No repacking or source repository migration is performed. Fetch and clone storage formats remain Git-readable within the tested subset.

Worktree changes stage selected target files with the required attribute snapshot before applying them, hold index/HEAD/branch locks, retain original changed files in a temporary backup, and publish index/refs after file application. Ordinary file-application errors roll back before ref/index publication. A journal under `.git/git-next-checkout-*/` and its backups survive an interruption or index/ref-publication failure. Further add/commit/checkout/fast-forward operations refuse while such a journal exists. There is no automatic crash recovery yet: preserve the journal, `backup/` and `old-index`, inspect HEAD/refs and recover explicitly with reference Git. Multi-file/ref updates are not an atomic filesystem transaction. Staging adds disk I/O and space proportional to selected target files and required attributes; no universal faster-checkout claim is established.

`--version`, `-v`, `version [--build-options] [--json]` identify the product as git-next, including the copy named git. `doctor [--json]` reports the executing binary and replacement blockers without printing configuration or credentials. `compatibility --json` embeds the declared feature gates in the binary.

A preview uninstall removes only the installed command if its checksum still matches; repositories, global Git configuration and original Git remain. Full system replacement requires a separately validated compatibility matrix, executable backup, atomic activation and verified rollback. That gate is currently closed.

[Filesystem discovery](NATIVE_DISCOVERY.md) and the [managed Windows GCM subset](CREDENTIALS.md) have isolated fixture acceptance. Generic DPAPI/HTTPS Get does not establish provider UI/token renewal, real vault migration or full credential parity. Version identity remains git-next.
