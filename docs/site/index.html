git-next

The 1.0.3 distribution uses a source-built native C Git engine with git-next's identity, LF policy, language support and installation/update behavior. Native packages include their owned runtime; existing repositories, Git configuration, hooks and credential-helper contracts retain their normal behavior. Local correctness and paired performance gates are complete within the recorded scope. Release staging, workstation activation, push and publication are tracked separately in delivery status.

Independent Rust preview package

The preview packages the independent Rust client. Go tooling also builds the native C distribution and its installers; these are separate artifacts with separate acceptance scope. The 115-file Python retirement preserves the applicable build, packaging, migration and maintenance capabilities in Go, while necessary platform scripts remain. Tooling and migration evidence.

go -C tools/devtool run . package-rust --platform windows-x64 writes a zip of the Rust git, LFS entrypoints, and Git-Terminal. The zip contains no MinGW, Bash, Perl, Python, or Git for Windows files. Its install.ps1 copies them to %LOCALAPPDATA%\Programs\git-next and does not replace a registered official Git directory. See installation.

Windows one-click installation

After obtaining the official release's install.ps1, run powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1. This automatically replaces registered Git for Windows, preserves configuration/login/repositories and records a protected rollback transaction. -Plan inspects the selection without changes. Offline MSI/TLS material and checksum requirements are documented in installation.

Windows MSI installs the independent Rust + GPUI Fast Git-Terminal beside Git-next, with tabs, Unicode/IME, copy/paste, scrollback and owned Bash plus PowerShell/CMD profiles. It replaces the Git Bash desktop entry and adds no Git GUI menu. Built-in LFS and game profiles cover Unity/Tuanjie and Unreal; no separate LFS installer is needed.
