git-next

简体中文 · Manual · Delivery status

git-next is a complete source-built Git client with its own product identity, cross-platform LF defaults, and native English/Simplified Chinese messages. The primary engine is the full native C command, repository and protocol implementation based on Git 2.54.0; it does not fall back to an installed Git or OpenSSH. Existing repositories, Git configuration and credential helpers keep their normal contracts.

Version 0.3.0 passed the consolidated local correctness and paired performance gates. Final publication and workstation takeover are tracked separately. Current acceptance distinguishes implementation, testing, publication and installation.

git --version identifies git-next and its compatibility baseline. Normal Git commands, plumbing, hooks, signing, LFS, credential helpers, submodules and linked worktrees use the full native engine. User-configured hooks, filters and helper programs retain their normal Git behavior.

Unconfigured text uses LF consistently across platforms. Explicit repository attributes, binary/LFS rules and configuration retain their priority. New repositories remain empty after init. git eol --apply explicitly installs missing shared LF/editor policy; it does not silently rewrite every existing project. Pure line-ending changes are compared canonically, while content/serialization changes remain visible. LF policy.

Language follows system preferences and supports persistent and per-command overrides. Machine formats remain stable. Automatic updates select official GitHub metadata, probe official/mirror download routes concurrently and verify downloaded bytes; mirrors cannot choose the release or provide its trusted identity. Evidence and source

Validation runs locally, with independent correctness lanes in parallel and Windows Installer transactions serialized. Reports retain actual elapsed time and failures. Performance uses a separate paired batch; measured medians, p95 and primary-process memory determine claims. No universal speedup is promised. Builds · Performance · Compatibility.

The native core is GPL-2.0-only with the declared dependency licenses and corresponding source bundles. Source/license delivery. No GitHub Actions are used.

Historical Rust preview

The currently installed preview is a self-contained, experimental Git client built in Rust using Gitoxide and Russh. The intended command is git. New repositories default to main; existing repositories keep their branches and object layout. Runtime code does not launch Git or OpenSSH as a fallback.

This version is not a complete Git replacement. Native push, clean-worktree switch/checkout and two-parent merges are implemented in the declared subset. Native LFS pointers/cache/filters and HTTPS batch/basic transfer are available in the declared subset. Complete merge/recovery, rebase, LFS/CLI/IDE behavior and existing-login migration remain open. The installer blocks system replacement and installs a separate git-next preview. Do not use it as an IDE's Git executable or on a production Git server yet. No universal speedup or memory claim has been established. Full workstation takeover requirements.

Try it

Requires Rust 1.96+ and the platform's native compiler. Source installation resolves an official full commit SHA first, tries GitHub, then pinned GitHub transport mirrors if needed. Official SHA lookup fails closed; credentials and signatures are not obtained from mirrors. Mirror availability is not guaranteed.

Windows PowerShell, after downloading and reviewing install.ps1 from this repository:

./install.ps1
# Open a new terminal
git-next --version
git-next version --build-options
git-next doctor --json
git-next compatibility --json

Linux x64/ARM64 or macOS ARM64, after downloading and reviewing install.sh:

sh install.sh
~/.local/bin/git-next --version

The preview command is git-next; a copy named git is stored outside PATH. Existing Git, credentials, SSH configuration and repositories are preserved. -ReplaceGit / --replace-git deliberately refuse while full parity is false. macOS Intel is not a supported target. Installation and removal.

Architecture and performance

Gitoxide supplies Git storage/protocol/index primitives; Russh supplies the built-in SSH transport. Local clones copy missing objects into an isolated temporary repository before publishing the destination, without hard links or source mutation. Fetch reuses existing objects. Worker caps avoid unbounded parallelism. Unsupported operations return errors instead of silently delegating to installed Git.

--version, -v, version, and version --build-options identify git-next; --json provides machine-readable product/engine identity. doctor --json lists the current replacement blockers. Version queries use a direct startup path without repository discovery or SSH setup.

Performance must be measured per operation, repository, transport and cache state. The status scanner uses one worker per 2000 index entries, capped at eight, to avoid starting one worker per logical CPU on small repositories. Measurement policy and local benchmark. Complete Git compatibility is the release prerequisite for replacing a working installation.

Repository terminal

git-terminal --cwd PATH opens a native repository shell with the isolated preview. Windows: PowerShell 7 or Windows PowerShell, Start menu shortcut, optional folder context menu. Unix: native shell. See terminal setup. Bash/POSIX emulation and full Git replacement remain separate unfinished compatibility goals.

System configuration uses filesystem-only discovery. Verified standalone Windows GCM support retains an existing named helper and uses native git-next callbacks. See native discovery and credentials; real-account migration and full takeover remain open.

Local LF/configuration/operation suites run in Linux x64 Docker and emulated Linux ARM64 containers. Exact accepted suite counts and source/binary identities are recorded in acceptance. Native Mac/physical ARM64, complete Linux/network performance and provider acceptance remain separate requirements.
