单一路线与执行顺序

2026-10-21 当前进度：实现项 7/7，完整交付项 7/10。新终端已通过 14 项真实桌面检查，耗时 23.184 秒；标签页、目录/分支、命令高亮和中文文本均有截图与记录。组合验收发现用户 MSI 内 PowerShell 初始化失败，现已实现独立无控制台启动器并通过针对性检查，等待重建后的 MSI 生命周期验收。此前未发布的 MSI 已卸载，本机仍由官方 Git 提供命令；正式发布和本机接管尚未完成。

主路线固定为从已固定的上游源码构建并维护 git-next 原生兼容核心，整合本产品的身份、LF、语言和安装更新行为。停止逐个重写 Rust Git 子集来追赶完整 Git，也停止新的目录扫描性能分支。Rust 既有代码只在明确需要的独立配套边界使用；GPL 核心和其他组件的许可、运行时边界、源码交付仍须在 D02/D07 解决。不得调用本机已安装的 Git/OpenSSH 充当运行时兜底。

  1. 完成 D01–D04 的核心、运行时、LF 和语言整合。
  2. 完成 D05–D07 的 MSI、自动更新、五平台完整包及最终统一回归输入。期间允许必要的编译、静态语法检查和文档生成，不运行功能回归、安装试验或性能测试。
  3. D01–D07 全部关闭后才启动 D08。独立临时仓库检查可批量并行，MSI/系统集成串行执行；Docker 使用生成账号并清理本任务资源。禁止再要求个人私有仓库或重复探测真实账号。
  4. 收集本批失败后统一修复，再核验受影响检查和最终候选产物。不承诺测试只运行一次就必然无错，也不回到每完成一个小功能就执行多轮测试的方式。
  5. 正确性通过后执行 D09，所有性能场景作为同一批处理，不与构建、回归或模拟器并发。慢于参考 Git 的结果必须列为待修复或明确未达标，不能宣称普遍更快。
  6. D08/D09 通过后才完成 D10；仅发布一个汇总版本。最终交付前的接管演练必须可回滚，最终默认命令安装以实际 Windows 调用结果为准。

git-default-v2 布局重构（2026-10-22）

本节记录在 v0.3.0 发布之后发生的安装布局变更，不改写上面各批次的历史结论。

HTTPS 克隆修复、克隆基准与生产就绪清单（2026-10-22）

本节记录网络传输缺陷的修复、clone 实测方法与结论，以及生产就绪的差距清单。

传输缺陷（已修）：http.sslcaInfo 指向 rustls 无法解析的证书捆绑（Windows 上常见的 curl ca-bundle.trust.crt）时，之前会让所有 HTTP 与 HTTPS 远端直接失败，连纯 http:// 也被牵连——因为 HTTP 客户端在判断 URL scheme 之前就构建了 TLS 配置。现在 TLS 设置只作用于 https://，捆绑解析不出证书时回退默认信任库而不是中止连接。本机修复前 http://127.0.0.1 克隆直接报 Configured TLS CA bundle has no certificates，修复后正常。

克隆优化：fetch 之后原本重新 open 一次刚克隆的仓库再做检出，该次重开会重读配置并重扫 pack 目录；现直接复用 fetch 返回的仓库句柄。另新增 GIT_NEXT_TRACE_TIMING=1 阶段计时， 把克隆拆成「传输+索引」与「检出」两段。

实测（gitsss 本地服务端，HTTP，3000 文件 / ~100MB / 12.7MiB pack，9 轮交替采样）： Git 2.55.0 中位 3379ms，git-next 中位 2726ms，快 1.24×（-19.3%）。 服务端访问日志显示每次克隆有 2.0–2.9s 花在服务端（info/refs 370–720ms、协商 370–640ms、 打包 1000–2000ms），客户端实际工作约 0.5–1.0s。Windows 上 git upload-pack 单次启动约 360ms， 因此该结论低估了客户端贡献；该占比在 Linux 服务端会大幅下降。

GitHub 对照：本沙箱经拦截代理访问 GitHub 的 TLS 握手不稳定（unexpected eof / tls handshake eof），无法给出可靠的克隆数字，已在文档中标注为未测并给出复现命令。 可测得的是单请求路径：ls-remote 约 1020ms 对 1990ms（探索性，3 次）。
